# 码栈 Web 设计与交互提示词

使用时先复制「总提示词」，再附上需要的页面提示词和「验收提示词」。设计出图可附产品评审稿。交给 Codex 实现时，同时提供当前服务端代码。

## 参考依据

- 掘金首页信息流按标题、摘要、作者、阅读与点赞数据、标签组织信息。码栈可沿用这种扫读层级，用自己的标识、色彩和组件细节呈现。[掘金首页](https://juejin.cn/)
- 首页公开 CSS 中，`.main-header` 使用主题变量和吸顶规则，`.list-header` 用细分隔线组织列表导航，选中与悬停以蓝色强调，`.sidebar-block` 使用浅底、轻阴影、小圆角。把这些规则转化为码栈的层级、边界和状态反馈。[全局 CSS](https://lf-web-assets.juejin.cn/obj/juejin-web/xitu_juejin_web/app.c7efecd.css) · [布局 CSS](https://lf-web-assets.juejin.cn/obj/juejin-web/xitu_juejin_web/layouts/default.a1d6163.css) · [首页 CSS](https://lf-web-assets.juejin.cn/obj/juejin-web/xitu_juejin_web/9.8b63fa2.css)
- 页面范围以[产品评审稿](./product-review.html)为依据，当前可接入能力以 [server.mjs](../server.mjs) 为依据。[前端开发文档](./frontend-development.md)中的 React 双入口、审核和游标分页属于规划。

## 总提示词

> 为「码栈」开发者社区设计一套中文 Web 前台。用户可以浏览技术文章、交流开发动态、阅读小册和查看作者。界面优先支持连续阅读和快速扫读。使用码栈字标、独立配色和自有图标，采用浅色页面底、白色内容区、细分隔线与克制的阴影。标题、摘要、元信息依次降低视觉权重。页面只保留有用途的入口和文案。
>
> 为码栈定义并复用 CSS 变量。设计起点为背景 `#F3F6FA`、内容面 `#FFFFFF`、主文字 `#17243A`、次文字 `#52627A`、边线 `#DCE4EE`、主色 `#294CBD`、选中底色 `#EAF0FF`。使用系统中文字体，列表标题 17px、摘要 14px、元信息 13px、详情正文 16px/1.75。使用 4px 间距基准、8–12px 容器圆角。链接、标签、选中项、按钮和焦点环共用主题变量，选中状态同时提供字重、下划线或描边。
>
> 顶栏建议高 60px，放品牌、文章、沸点、小册、搜索与账号入口。桌面内容居中，最大宽度建议 1240px，首页三栏可从 180px / 弹性主栏 / 240px 和 20px 栏距起步。低于 1024px 时把辅助模块移到主区之后，低于 768px 时使用单栏，将分类移入可横滚的筛选条，目录收进可展开面板。键盘焦点清晰可见，触屏操作区建议至少 44px，吸顶内容让出锚点和焦点空间，交互过渡尊重减少动态效果偏好。
>
> 为每个异步区域设计加载、空态、失败和重试。表单提交期间防重复，失败保留输入，在相关字段或操作附近显示反馈。游客点发布、点赞、收藏、评论、关注或签到时先引导登录，登录后回到站内原页面。写入成功后用服务端状态更新按钮和统计。使用团队确认的真实内容和权限。当前原型由 Node 服务静态托管，UI 路由需适配现有入口或先验证刷新直达支持。

## 首页与搜索

> 顶栏下按标签、文章列表、辅助区分栏。中央提供「推荐、最新、关注」，每条文章放标题、最多两行摘要、作者、阅读/点赞/评论和标签。标题进入详情，作者与标签各自有独立点击区。签到或热门标签可放右侧，活动入口待数据接入。搜索回车提交并提供清除操作；切换筛选时回到列表顶部，返回列表恢复标签、关键词和滚动位置。清空条件可从无结果页返回默认列表。慢请求返回时只展示当前条件的数据。
>
> 使用 `GET /api/feed` 的 `kind=article`、`tag`（标签 ID）、`q` 和 `tab`。推荐传 `recommended`，关注传 `following`，最新走默认顺序。标签来自 `GET /api/tags`。当前列表无游标参数，避免展示无法加载的下一页。顶栏若在其他页面发起搜索，可转到文章列表并带入关键词。

## 文章详情与评论

> 桌面左侧布置点赞、收藏、评论跳转，中间呈现标题、作者、阅读量、正文和评论，右侧放作者、目录和相关推荐。目录与正文使用同一组标题锚点，支持中文和重复标题。移动端将操作合并到正文附近的操作区，宽代码块在容器内横滚。评论展示真实作者，发送前检验去掉首尾空白后的内容，失败保留编辑内容。本人文章隐藏关注入口。
>
> 详情使用 `GET /api/posts/:id` 的 `post`、`following`、`comments`、`related`。进入文章时按既定计数需求传 `view=1`，互动后的刷新省略该参数。点赞、收藏和关注提交布尔 `active`，评论提交 `body`。找不到内容时提供返回列表入口。

## 沸点与发布

> 沸点以话题筛选、发布区和时间流为主体，短内容卡片放作者、正文、可选图片和互动。发布输入提供正文计数、单图预览及移除、单标签选择和提交反馈。使用 `kind=pulse` 请求内容流，精选传 `tab=featured`。沸点正文上限 2000 字符。
>
> 文章发布提供标题、Markdown、预览、单标签和可选系列名，宽屏可并排编辑预览，窄屏可切换。标题上限 120，正文上限 60000，系列名上限 60。两种内容均通过 `POST /api/posts` 创建，拿到返回 ID 后进入相应内容或刷新列表。草稿、编辑、审核与审核结果界面依赖后续接口。签到状态以 `GET /api/me` 的 `checked` 和签到响应为准。

## 小册与个人主页

> 小册列表按分类和难度筛选，卡片呈现标题、分类、难度和章节数。详情先展示小册信息，再按顺序展示章节及相关小册。优先提供公开阅读入口。列表接入 `GET /api/courses` 的 `category` 和 `level`，详情接入 `GET /api/courses/:id` 的 `course`、`lessons`、`related`。
>
> 个人主页展示头像、昵称、简介、个人网站与成就统计。自己的主页提供编辑资料，其他作者主页提供关注。根据 `GET /api/users/:id` 的 `posts`、`stats`、`follows` 等字段组织页面。产品评审稿拟将收藏与点赞记录设为仅本人可见，当前接口会向访问者返回这些字段。只有服务端补齐访问控制并验证后，才可将其作为私有功能交付。登录用用户名和密码，注册增加昵称，账号状态从 `GET /api/me` 读取。

## 验收提示词

> 检查 1440、1024、768、390px 和 320px 视口的阅读宽度、焦点顺序和内容溢出。用游客和两个测试账号检查首页筛选、搜索、返回恢复、登录回跳、发布、签到、关注、点赞、收藏和评论。用慢请求和失败请求检查无结果、重试、连点保护、旧响应覆盖和输入保留。检查中文以及重复标题的目录跳转。核对每个交互的真实请求、响应、权限和刷新后状态，标出只完成视觉稿的功能。
