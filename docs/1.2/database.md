# PostgreSQL 数据库设计 1.2

## 数据模型与迁移依据

`prisma/schema.prisma` 描述 Prisma 可表达的实体、关系及索引名。`prisma/migrations/` 同时保存 SQL 级 CHECK、触发器和数据兼容步骤。部署使用版本化迁移。迁移成功后重新生成 Prisma Client，保证应用访问的新列、关系和类型同步。

当前业务实体使用 UUID。收藏、点赞、关注、标签关联等以组合主键防止重复。时间点采用 `timestamptz(3)`；签到以北京时间自然日读取和保存 `local_date`。

| 模块 | 实体与关键约束 |
| --- | --- |
| 账号和权限 | `users` 保存身份、角色和状态；`sessions` 保存令牌摘要、过期和撤销时间。用户名唯一，注册先规范化。 |
| 文章 | `articles` 保存内容、审核状态、公开状态和版本。公开状态要求有发布时间和已通过审核。标签、点赞和阅读窗口分别落在 `article_tags`、`article_likes`、`article_view_windows`。 |
| 沸点 | `pulses` 保存发布状态、正文或图片、精选号及阅读数。标签、点赞与阅读窗口各用关系表。正文和图片至少一项，图片最多四张。沸点话题计数和公开榜单过滤非公开沸点。 |
| 文章、沸点评论 | `comments`、`pulse_comments` 使用可空 `parent_id`。每棵树最多两级，回复与父节点属于同一内容。可见性检查位于 API 查询和写入事务。两个点赞表均按用户和评论组合主键去重。 |
| 课程 | `course_categories`、`courses`、`course_lessons`、`course_lesson_comments`。章节位置在同一小册内唯一且从 1 开始。评论按章节隔离。 |
| 收藏和关注 | `article_bookmarks` 按用户和文章唯一，具名合集由 `(user_id, collection_id)` 组合外键限制为本人所有。空集合表示默认收藏。`user_follows` 禁止自关注。 |
| 活动与签到 | `activities` 保存展示区间、顺序及乐观锁版本；`checkins` 每位用户每天最多一条。 |
| 审核和通知 | 文章、沸点和评论的审核日志保存操作人及状态变化。`notifications` 按收件人、类型和目标去重，保留历史通知。 |

## 评论结构约束

新增迁移 `202611250020_comment_thread_integrity` 在同一事务中锁定两张评论表，先检查存量，再安装触发器。发现跨内容、三级或自引用数据时迁移失败，原记录保留以便人工核对。

- 一级评论的 `parent_id` 为空。二级评论必须引用同表、同一内容的一级评论。
- 插入时检查父节点并持有行锁。评论创建后，ID、所属内容和父节点不可改变。正文与审核状态仍可更新。
- 父节点隐藏不删除评论树。公开列表、互动和计数按父子可见状态过滤。
- 现有删除规则继续使用各自的外键。物理删除有回复的文章一级评论会被拒绝，沸点一级评论的物理删除会级联其回复。管理后台使用隐藏操作。
- 章评为平铺结构，章节与课程均公开时才能读取或新增。

## 索引与一致性核对

收藏分页索引按用户、合集、创建时间和文章 ID 查询。Prisma 显式映射 PostgreSQL 已存在的物理索引名，保留历史迁移和已建索引。迁移后使用 `prisma migrate diff` 对比 Prisma 可见结构，并用 PostgreSQL 目录和直写测试单独核对 CHECK 与触发器。
