数据库设计 v1.1

先验证用户注册与登录，再跑通文章发布、列表和详情，随后接入独立管理后台。前台和后台使用 React，共用 Node.js API 和 PostgreSQL，数据访问与版本化迁移使用 Prisma。

实施顺序

  1. 注册与登录。先迁移 users、sessions，接通注册、登录、当前用户及退出。验收重复注册、错误密码、会话失效和重启后的持久化。
  2. 文章主链路。接入文章、标签和标签中间表。验收作者发布后，游客能从列表进入 Markdown 详情，草稿和下架文章无法公开访问。
  3. 管理后台。另建 React 后台入口，共用同一 API 服务。启用管理员文章审核、下架、评论隐藏与恢复，记录每次状态变更。点赞、收藏和关注接入各自的关系表。

第二步拟在开发验收环境验证直接发布。第三步上线时，正式发布改为提交审核，由管理员审核通过后公开。如果前两步也要公开部署，发布入口等审核能力就绪再启用。

这份文档是本轮数据库评审基准。沸点、小册、收藏集分组等后续功能各自分阶段设计和迁移。

账号与会话

账号暂按用户名和密码注册。下表中的 UUID 为 PostgreSQL uuid，时间为 timestamptz。除标注可空外，字段均为必填。PK、FK、UQ 分别表示主键、外键和唯一约束。

表字段约束与规则
usersid uuid、username varchar(32)、password_hash text、display_name varchar(80)、avatar_url text?、bio text?、website_url text?、role UserRole、status UserStatus、created_at、updated_atPK id，UQ username。登录名规范化为 ASCII 小写后写入和查找。角色 USER / ADMIN，注册固定 USER。状态 ACTIVE / DISABLED，默认 ACTIVE。
sessionsid uuid、user_id uuid、token_hash text、expires_at、revoked_at?、created_atPK id，FK user_id → users，UQ token_hash。数据库存随机令牌摘要。注销撤销当前会话，禁用账号后既有会话也失效。

密码拟用 Argon2id 加盐哈希，保存带参数的编码摘要。登录校验哈希后签发随机会话令牌，浏览器通过 HttpOnly Cookie 持有令牌。公开接口与登录响应的 JSON 均排除密码哈希和会话令牌，日志同样排除两者。

文章与标签

users 1 : N articles  ｜  articles 1 : N article_tags N : 1 tags
表字段约束与规则
articlesid uuid、author_id uuid、title varchar(160)、body_markdown text、summary text?、status ArticleStatus、review_status ReviewStatus、version integer、published_at?、created_at、updated_atPK id，FK author_id → users。默认草稿、未提交，版本从 1 开始。时间字段 published_at 在发布时写入。正文存 Markdown 源文本，渲染层处理 HTML 和链接安全。
tagsid uuid、slug varchar(64)、name varchar(60)、created_atPK id，UQ slug。发布时选择已有标签。
article_tagsarticle_id uuid、tag_id uuid、created_atPK (article_id, tag_id)。分别引用 articles 和 tags。Prisma 显式建模为 ArticleTag，一篇文章可挂多个标签，一个标签可被多篇文章使用。

社区活动

activities 独立存储首页右栏活动。管理员在后台创建、编辑、调整排序、发布和下架，游客可读当前展示期内的已发布活动。

状态迁移

文章公开状态 DRAFT / PUBLISHED / UNLISTED 分别表示草稿、已发布、下架。审核状态 NOT_SUBMITTED / PENDING / APPROVED / REJECTED 单独记录。公开列表和详情统一约束 status = PUBLISHED。

动作原状态结果操作人
提交审核DRAFT，未提交或已驳回DRAFT + PENDING作者
审核通过DRAFT + PENDINGPUBLISHED + APPROVED，设置发布时间管理员
审核驳回DRAFT + PENDINGDRAFT + REJECTED，保留原因管理员
下架PUBLISHED + APPROVEDUNLISTED + APPROVED，保留上次审核结果与下架原因管理员
转回草稿UNLISTED + APPROVEDDRAFT + NOT_SUBMITTED，保留历史操作记录作者

首版草案允许编辑未提交或被驳回的草稿。待审版本锁定，已发布文章的在线修订另行设计。每次内容、标签或状态变更递增版本。提交、审核、下架使用预期版本和原状态作为更新条件，冲突返回 409。状态更新和审核记录在同一事务提交。评论状态变更与操作日志也使用一个事务。

共用接口与权限

React 前台与独立管理后台调用同一个 Node.js API。服务端统一做请求体、路径参数和查询参数的校验，再按路由执行会话校验、角色校验和资源归属校验。数据库查询使用 Prisma 绑定参数，响应字段按访问场景显式选择。

POST /api/auth/login		游客可用。验证用户名、密码及注册资料，注册固定 USER，重复用户名返回 409。无效凭据返回通用 401。
GET /api/auth/me

索引、约束与迁移

  • 公开文章按 published_at DESC, id DESC 游标分页。建立 articles(status, published_at, id)、articles(author_id, status, updated_at) 和审核队列索引 articles(review_status, updated_at, id)。
  • 反向查询建立 article_tags(tag_id, article_id)、article_likes(article_id, user_id)、article_bookmarks(article_id, user_id)、user_follows(followee_id, follower_id)。评论及审核记录按目标 ID、状态（如适用）和时间索引。会话按用户、过期时间分别建索引。
  • Prisma 模型用显式关系及组合主键，映射到本文的表名。数据库层用外键及唯一约束保护关系。自关注检查、发布状态与发布时间约束等纳入 SQL 迁移，随迁移一并评审。
  • 审核与内容保留策略优先用下架、隐藏或停用状态。常规接口保留审核记录，物理清除时先确认关联数据与日志保留要求。
  • 按账号、文章、后台、互动和活动划分版本化迁移。每批在独立 PostgreSQL 环境验证唯一约束、外键、事务回滚、权限拒绝和重启后持久化。
