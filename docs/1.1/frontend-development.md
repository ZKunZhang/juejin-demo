# 前端开发文档

版本 v0.3，待评审。React 前台与 React 管理后台是两个独立入口，共用 Node.js API。后端契约见 [后端及数据库开发文档](./backend-database-development.md)。

## 项目结构和工具

| 模块 | 工具 | 用途 |
| --- | --- | --- |
| 工程 | React、TypeScript、Vite、npm workspaces | 拟用 `apps/web` 和 `apps/admin` 两个入口，共享 `packages/api-client`。开发时各自代理 `/api`，生产由网关在各站同源转发到同一服务。 |
| 路由 | React Router | 公开页、登录跳转、创作者页和后台入口。回跳地址仅接受当前应用内路径。 |
| 数据 | Fetch、TanStack Query | 统一凭据、错误格式、请求取消、缓存与失效。切换账号时清理私有缓存。 |
| 表单 | React Hook Form | 登录注册、文章编辑、审核原因及评论提交。前端做必填、长度和格式反馈，后端做最终校验。 |
| Markdown | react-markdown、remark-gfm、自定义 remark 标题插件 | 编辑预览和公开详情共用渲染器。支持 GFM、目录锚点和重复标题；禁用原始 HTML，链接及图片限制协议。 |
| 界面 | CSS Modules、共享 CSS 变量 | 前台沿用评审稿三栏布局。后台采用侧栏、工作列表与审核详情。窄屏优先展示内容和主要操作。 |
| 验证 | Vitest、React Testing Library、Playwright | 组件、表单、状态展示及真实多账号浏览器链路。 |

Markdown 渲染由 [react-markdown](https://github.com/remarkjs/react-markdown) 和 [remark-gfm](https://github.com/remarkjs/remark-gfm) 实现。目录插件与正文标题共享同一组 ID，避免两个解析器产生不同锚点。验收覆盖中文、重复标题和不安全链接。

## M1 登录注册

- 页面采用 `/login`、`/register`。启动时调用 `GET /api/auth/me`，根据响应确定游客或已登录状态。会话 Cookie 由浏览器管理。API 客户端向当前站点的 /api/auth/csrf 获取令牌，为写请求添加 X-CSRF-Token，切换会话时清除并重新获取。
- 注册输入用户名、昵称和密码。登录仅输入用户名和密码。提交时防重复点击，用户名冲突显示在对应字段。退出后清除私有缓存并返回公开页。
- 前台访问创作者页时保留站内目标。后台普通用户访问时显示无权限，服务器仍独立验证 ADMIN。

## M2 文章发布、列表和详情

| 页面 | 实现要求 |
| --- | --- |
| `/creator/articles` | 查看自己的草稿、已发布及下架文章，并显示审核状态。 |
| `/creator/articles/new`、`/creator/articles/:id/edit` | 编辑标题、摘要、Markdown、标签。保存携带当前 version。冲突时保留未提交的输入，提示刷新服务器版本。 |
| `/` | 左侧标签、中间列表、右侧活动区域。文章列表支持标签和游标，筛选变化时重置游标。活动接口在后续阶段接入。 |
| `/articles/:id` | 左侧快捷操作，中间正文及后续评论，右侧作者、目录和推荐区域。公开详情只渲染已发布内容。 |

M2 在隔离的开发与测试环境提供临时直接发布。M3 将创作者按钮替换为提交审核。审核中的内容只读，驳回展示原因并允许编辑后重提。

## M3 独立管理后台

- `/login` 使用共用登录接口。后台每次启动重新检查会话与角色。角色变更后由接口返回权限错误并清掉后台缓存。
- `/articles` 以待审列表为主，详情用同一 Markdown 渲染规则。操作有通过、驳回、已发布文章下架。驳回和下架必须填写原因。
- `/comments` 查询文章评论及可见状态，可隐藏和恢复。隐藏需填写原因。状态冲突提示刷新。
- 成功操作后刷新队列与详情。使用键盘可操作表单、确认对话框和状态筛选。

## M4 多用户互动

- 评论区显示公开可见评论，提交成功后刷新列表。不同用户的评论分别显示真实昵称。
- 点赞、收藏、关注按目标状态提交。失败时保留上次确认状态。成功后刷新详情和个人列表，不在前端累加权威统计。
- 异常统一展示。400 提示字段错误，401 引导登录，403 告知权限不足，404 显示不可访问，409 提示刷新或处理冲突。
