# 码栈设计、交互与维护提示词

设计出图时复制「设计提示词」和对应模块的要求。实现时再附「交互提示词」。修改已有页面或验收交付时使用「维护提示词」。在提示词前补上本轮任务、目标页面和可复现的问题。

## 设计提示词

> 为「码栈」中文开发者社区设计本轮指定的页面。优先让用户快速扫读文章和动态、连续阅读正文、辨认当前位置并完成操作。参考掘金公开页面的信息组织，使用码栈字标、紫色主题和已有组件。
>
> 以 `apps/web/community.css` 与 `apps/web/styles.css` 为样式来源。使用浅色背景、白底内容面、细分隔线和轻阴影。前台主色使用 `--brand`，选中背景使用 `--selected`，普通说明用 `--muted`，容器圆角遵循 `--radius`。版式按标题、摘要、元信息依次降低视觉权重。正文用稳定的阅读行距，代码块和宽表格独立横滚。
>
> 桌面首页使用分类、内容流、辅助信息三栏；空间不足时优先保证主栏。移动端使用单栏，保留文章、沸点、课程入口，将长筛选条设为区内横滚。为键盘焦点、触屏操作、长中文标题、字号放大和减少动态效果准备表现。设计稿给出桌面、移动端、键盘聚焦和至少一个异常状态，并标清复用的组件与样式变量。

参考页面为[掘金推荐页](https://juejin.cn/recommended)。实现入口为[前台路由](../../apps/web/main.tsx)和[后台入口](../../apps/admin/main.tsx)。

## 交互提示词

> 按任务写明用户入口、触发方式、反馈、权限和刷新后的结果。异步区域按实际场景提供加载、空态、失败和重试。防止写入连点，提交失败保留输入，提示靠近触发位置。游客触发需登录的操作时保留站内返回位置。使用现有的表单、选择器、对话框和查询缓存，检查键盘操作、焦点返回、浏览器前进后退以及窄屏可达性。
>
> 实现前沿界面调用追到服务端路由，核对请求参数、响应、角色和错误状态。接口以当前运行的 `/api/openapi.json`、已注册路由和真实响应为依据。需求超出现有行为时，标明缺口和受影响的页面，待确认接口后再接入。

## 模块要求

| 模块 | 设计与交互要求 |
| --- | --- |
| 文章首页与搜索 | 推荐、最新、关注的选中状态清楚。保留标题、最多两行摘要、作者和互动数据的层级。验证筛选与搜索组合、无结果恢复、切换请求时的结果归属。 |
| 文章详情与评论 | 展示标题、作者、正文、目录及互动。验证中文与重复标题的锚点、窄屏代码块、评论排序、回复、点赞，以及发送失败后保留文本。 |
| 沸点与排行榜 | 发布区显示话题、输入、图片预览及反馈。动态突出作者、正文、话题和操作。单独验证评论预览到详情的跳转、榜单长昵称和移动端两侧辅助模块的排布。 |
| 课程目录与阅读 | 区分课程列表、介绍、章节目录和正文。验证分类与难度组合、课节切换、当前章节、深链接和课程评论。 |
| 个人主页、收藏和通知 | 区分本人和访客的页面入口及可见内容，核验收藏夹选择和访问权限。通知用独立标记区分已读、未读，检查跳转和刷新后的状态。 |
| 创作者中心 | 保留草稿、编辑预览与提交审核的路径。验证失败保留输入、草稿刷新恢复，以及审核状态与公开可见性的对应关系。 |
| 管理后台 | 复用后台控制样式，保留表格的扫描顺序。验证日期筛选、分页、空结果和失败重试。审核操作验证权限、确认反馈及刷新后一致性。 |

## 维护提示词

> 每次页面改版、主题变量调整、路由或接口变化、出现样式回归时，更新本页受影响的规则，并在模块测试文档记录实际验证结果。先复现问题并定位到真实入口与样式来源。优先调整对应模块，修改共享变量后检查其他引用页面。
>
> 运行 `npm run typecheck` 与 `npm run build`。浏览器检查 320、390、768、1024、1440px，覆盖受影响的页面、导航、键盘焦点、正文横滚和空错误状态。涉及持久化或权限时，用游客、本人和其他账号检查，后台操作加管理员角色。用对应已有浏览器脚本验证业务路径，需要截图对照时记录路由、视口和账号角色。
>
> 每轮记录改动模块、复现入口、实际执行的验证和剩余差距。构建、访客冒烟检查和真实登录业务验证分别记录。样式与规范冲突时，结合实际页面确认本轮预期，再同步更新提示词。

脚本和环境配置参见[项目 README](../../README.md)。模块回归与证据记录在[模块测试用例](./module-test-cases.md)。
