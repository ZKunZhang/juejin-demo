# 创作者中心与发布工作台设计 v1.2

本文面向产品、前后端开发和测试人员，描述当前码栈创作者中心、文章编辑器及发沸点入口的实现。创作操作以登录会话中的用户为作者，文章先保存草稿再提交审核，沸点直接提交待审内容。本版按 2026 年 11 月 25 日的代码整理，验收项用于后续回归，实际执行结果以对应测试记录为准。

## 页面与入口

| 入口 | 页面职责 | 身份要求 |
| --- | --- | --- |
| `/creator` | 账号卡片、数据概览、近期文章和沸点、活动及话题 | 登录用户 |
| `/creator/articles` | 当前作者全部文章，按更新时间和 ID 倒序 | 登录用户 |
| `/creator/articles?status=draft` | 当前作者可继续编辑的草稿 | 登录用户 |
| `/creator/articles/new` | 创建文章、预览、保存和提交审核 | 登录用户 |
| `/creator/articles/:id/edit` | 读取本人文章，按状态允许编辑或只读 | 文章作者 |
| `/pulses#publish` | 聚焦沸点发布输入区 | 发布要求登录 |

顶栏「创作者中心」旁有快捷菜单，包含写文章、发沸点和草稿箱。点击菜单外部、切换页面或按 Esc 会收起菜单。游客进入时使用登录弹窗并保存站内目标。文章编辑路由隐藏全局顶栏，给标题、Markdown 和预览留出空间。相关实现见 [前台路由](../../apps/web/app/web-app.tsx)、[创作者页面](../../apps/web/features/creator/creator.tsx)和[文章工作台](../../apps/web/features/articles/articles.tsx)。

## 数据概览与内容范围

`GET /api/me/creator` 根据当前会话的用户 ID 聚合资料和统计，通过数据库事务读取。响应包含 `profile`、`stats`、`recentArticles` 和 `recentPulses`，设置 `Cache-Control: private, no-store`。

| 字段 | 计算范围 |
| --- | --- |
| `profile.avatarUrl`、`profile.createdAt` | 本人资料和入站时间 |
| `stats.followers` | 关注本人的有效用户数量 |
| `stats.following` | 本人关注的有效用户数量 |
| `stats.views` | 本人已发布文章的累计阅读量之和 |
| `stats.likes` | 本人已发布文章获得的点赞关系数量 |
| `stats.comments` | 本人已发布文章中的可见评论，回复同时要求父评论可见 |
| `stats.bookmarks` | 本人已发布文章被收藏的关系数量 |
| `recentArticles` | 本人最近更新的 6 篇文章，包含发布和审核状态 |
| `recentPulses` | 本人最近创建的 6 条沸点，包含正文和创建时间 |

下架文章的阅读、点赞、评论和收藏均不进入上述文章统计。近期内容切换只改变当前卡片，不跳转页面。活动卡片读取公开活动接口后展示前 3 条，话题按公开沸点数取前 5 项。统计口径和响应字段见 [创作者 API](../../apps/api/features/creator/creator.ts)。

## 文章数据与约束

| 数据 | 字段及约束 |
| --- | --- |
| `articles` | UUID 主键，作者外键，标题最多 160 字符，摘要最多 500 字符，Markdown 最多 60000 字符，`version` 为正整数 |
| `article_tags` | 文章和标签组成主键，同篇文章最多提交 10 个不重复标签 |
| `tags.scope` | 文章只接受 `ARTICLE` 或 `BOTH` 范围的现有标签 |
| `article_review_logs` | 保存每次状态迁移的文章版本、操作、操作人、前后状态和原因 |

草稿可以暂时没有标题或正文。提交审核时服务端要求去掉首尾空白后的标题和正文均有内容。公开文章要求发布时间已设置且审核通过，这条规则同时由数据库 CHECK 约束保护。数据模型、校验和状态迁移分别见 [Prisma 模型](../../prisma/schema.prisma)、[文章 API](../../apps/api/features/articles/articles.ts)和[审核 API](../../apps/api/features/articles/moderation.ts)。

## 发布与审核状态

| 操作 | 前置状态 | 结果 | 执行者 |
| --- | --- | --- | --- |
| 创建草稿 | 新内容 | `DRAFT + NOT_SUBMITTED` | 登录作者 |
| 保存 | `DRAFT + NOT_SUBMITTED/REJECTED` 且版本匹配 | 更新内容，版本递增 | 文章作者 |
| 提交审核 | 可编辑草稿，标题和正文完整 | `DRAFT + PENDING`，版本递增 | 文章作者 |
| 审核通过 | `DRAFT + PENDING` | `PUBLISHED + APPROVED`，设置发布时间 | 管理员 |
| 驳回 | `DRAFT + PENDING` | `DRAFT + REJECTED`，保存原因 | 管理员 |
| 下架 | `PUBLISHED + APPROVED` | `UNLISTED + APPROVED`，保存原因 | 管理员 |
| 重新展示 | `UNLISTED + APPROVED` | `PUBLISHED + APPROVED` | 管理员 |
| 转回草稿 | `UNLISTED + APPROVED` | `DRAFT + NOT_SUBMITTED` | 文章作者 |

待审核、已发布和已下架内容在编辑器中只读。驳回后允许修改和重提，下架后作者先转回草稿。首次审批公开时生成关注者通知，重新展示保留原发布时间并且不补发首次发布通知。公开详情查询始终限制为已发布内容。

## API 契约

所有写请求经过来源和 CSRF 校验，再核验当前会话。客户端发送作者 ID 不会改变归属，额外参数由对象 Schema 拒绝。

| 方法与接口 | 请求 | 响应及行为 |
| --- | --- | --- |
| `GET /api/me/creator` | 无 | 本人概览，匿名返回 401 |
| `GET /api/me/articles` | `page`，可选 `status=draft` | 本人文章数组，每页最多 100 条 |
| `GET /api/me/articles/:id` | 本人文章 ID | 编辑数据、版本及最近驳回或下架原因，其他作者不可读取 |
| `POST /api/articles` | `title`、`bodyMarkdown`、`tagIds`，可选 `summary` | 201，返回已持久化草稿 |
| `PATCH /api/articles/:id` | 当前 `version`，可选内容字段 | 原子更新内容及标签，旧版本或不可编辑状态返回 409 |
| `POST /api/articles/:id/submit` | 当前 `version` | 提交审核，返回新版本 |
| `POST /api/articles/:id/return-to-draft` | 当前 `version` | 下架文章转回草稿 |
| `POST /api/pulses` | `body`、`images`，可选 `tagId` | 201，创建待审核沸点 |

文章草稿箱只包含 `NOT_SUBMITTED` 或 `REJECTED` 的草稿，待审文章进入全部文章列表。分页由页号偏移实现，当前客户端根据是否正好返回 100 条判断下一页按钮，最后一页恰好 100 条时可能继续进入空页。接口和调用见 [文章 API](../../apps/api/features/articles/articles.ts)和[文章工作台](../../apps/web/features/articles/articles.tsx)。

## Markdown 编辑交互

工作台由标题栏、格式工具栏、发布设置、正文输入、实时预览和底部计数构成。桌面默认双栏，用户可以切换编辑或预览。切换视图保留组件内的标题、正文、摘要及标签输入。

格式工具支持小节、粗体、斜体、引用、链接、图片、代码块和列表。插入针对当前选区，空选区使用示例文字，插入后恢复正文焦点及相应选区，超过正文上限时跳过插入。摘要和标签收在发布设置里，标签达到 10 个后禁用未选项。

预览和公开文章共用 `Markdown` 渲染器，启用 GFM，跳过原始 HTML，链接使用协议白名单。中文和重复标题通过统一标题插件生成稳定锚点。编辑器显示字符数、行数和已保存版本。[Markdown 渲染器](../../apps/shared/ui/markdown.tsx)

## 保存失败与恢复

保存或提交期间禁用重复操作。点击提交审核时，前端先创建或更新草稿，再调用提交接口。如果第二步失败，第一步的草稿已经持久化，工作台保留已保存行及输入，显示具体错误，用户可再次提交。

版本冲突返回 409，服务端不覆盖现有记录。前端保留当前输入并显示错误，但当前工作台尚未提供并排比较、合并或加载服务器版本的专门界面。浏览器刷新及关闭前也没有自动保存或离开确认，应按显式「保存草稿」成功反馈判断持久化状态。

## 沸点创作入口

创作者快捷入口跳到 `/pulses#publish`，发布区获得焦点。正文上限 2000 字符，最多四个不重复的 HTTPS 图片地址，可选一个适用话题，正文或图片至少有一项。创建时作者来自会话，状态默认为 `PENDING`，提交成功提示等待审核。

创作者概览的近期沸点目前只显示内容与时间，没有携带状态字段。完整审核结果应通过当前创作页面已有的结果入口核对，不能根据公开列表中暂时没有出现判定提交失败。沸点详情和公开评论只允许访问已发布沸点。[沸点 API](../../apps/api/features/pulses/pulses.ts)

## 验收基线

1. 游客从创作者入口登录后回到站内目标，普通用户只能读取和修改自己的草稿。
2. 两个账号分别创建文章，概览、草稿箱和统计不会串账号，已下架文章不进入公开文章统计。
3. 保存空草稿成功，缺标题或正文的审核提交失败，非法标签和第 11 个标签被拒绝。
4. 保存后刷新编辑页，标题、Markdown、摘要和标签一致。旧版本再次更新返回 409 且原输入仍在。
5. 选区加粗、代码块插入、双栏和预览切换可用，预览与公开详情采用相同 Markdown 规则。
6. 新草稿提交后变成待审只读，游客详情返回 404。驳回后可修改，下架后可转回草稿。
7. 创作者概览和编辑器在 1440、768、390 和 320px 下没有页面横向溢出。

已有自动化覆盖作者隔离、统计、草稿分页、关注文章流和浏览器编辑链路。测试源码提供可重复场景，本文件不代替某次执行结果。[接口测试](../../tests/creator.integration.test.ts) · [浏览器脚本](../../scripts/browser-creator.mjs)
